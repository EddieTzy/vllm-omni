Higgs v2 Triton decode-state fusion

Decision: retain as an experiment; no second upstream PR opened.
The state-update component improves, but the measured incremental serving
gain is small and first-audio p95 increases. More work is needed before
presenting this as a worthwhile production contribution.

Baseline branch: perf/higgs-v2-audio-routing.
Candidate branch: perf/higgs-v2-triton-state.
The baseline ALREADY contains uniform-audio routing from upstream PR #11068.
This branch stacks one additional state-update optimization on that baseline;
the earlier routing speedup is not counted again. Compare these two branches
to inspect only state fusion and its evidence.

Measured source base: 4dafb464442956996be9633ed036cd24ebfef1d0 plus routing
commit 30dcfdc205d17072734328e74c5ca96a882ec548. Measured model/kernel source
files are preserved byte-for-byte. SHA256 values: manifest.json.

Implementation:
One integer-only Triton launch, one program per active request, assembles BOS and
trailing EOS, preserves the final completed ramp-down frame, updates delay,
remaining-delay, termination and frame counters, and writes all eight
codebooks to a bounded 7-frame ring. A duplicated ring exposes chronological
history as a view; its last column supplies next-step feedback. Emitted frames
do not alias the reusable ring. Persistent slots use request IDs and are
released on MRv2 finish callbacks, preserving reordering and slot reuse.
Sampling, logits masking and RAS random draws stay in their original order.
CPU and V1 keep the original update path.

Experimental limits:
The existing CPU logits-mask/termination code still consumes scalar mirrors;
this version makes one batched GPU-to-CPU metadata copy per update. It does
not eliminate every host sync. The prototype pool capacity is 256; production
capacity/preemption handling and a dedicated upstream integration are still
needed. The measured snapshot is intentionally not reformatted or presented
as pre-commit-clean production code. No CUDA-graph/multi-GPU qualification.

Serving protocol:
C32 ONLY. A/B/B2/A2 independent boots; A/A2 routing-only, B/B2 routing+fusion.
32 warmups and 64 measured public EN/ZH prompts per boot, two waves of 32;
all requests and outputs retained. No extra concurrency sweep. Native C16
was not rerun for this optimization. All 256 measured requests succeeded.
Each arm also passed an HTTP stream-disconnect followed by WAV recovery;
this is not a server abort-acknowledgement or leak-proof claim.

RTF is mean(request latency/audio duration), not inverse aggregate throughput.
Latency includes HTTP, queueing, talker and codec; first audio arrives near
completion in this deployment. Unseeded output lengths vary. Two boots give
descriptive ranges, not a formal performance confidence interval.
The earlier routing experiment ran native C16 phases before raw C32, while
this experiment runs C32 only; do not add percentages or directly join their
absolute numbers as a single end-to-end comparison.

Validation:
Initial integer-kernel CPU-reference parity on B200: 998 cases.
Actual original/fused _dispatch_audio_codes with synthetic codes on CUDA:
150 consecutive steps, 4607 request-state checks, 85 request identities,
reordering, partial prefill, non-audio rows, EOS, cleanup and slot reuse.
History stays within 7 frames; the pool is fully released at test end.
Actual public model, matched C32 admission and initial audio RNG:
32/32 complete PCM byte-identical, 32/32 emitted-code histories identical,
179/179 normalized sampling/RNG events identical. Common diagnostic scheduling
and tracing are excluded from serving performance measurements.
Existing Higgs MRv2 regression module: 16 passed, 17 warnings in .10s.
Full repository CI and full perceptual/speaker-quality suites were not run.
